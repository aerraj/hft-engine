# Benchmark artifact guide

`linux/current.json` is an aggregate of twenty independent runs from public GitHub Actions, with median per-run percentiles (not a merged histogram). The aggregate preserves the worst maximum and overflow count across repetitions and includes min/max per-run tail ranges. CPU model is recorded and regression baselines reject cross-CPU comparisons. Each run contains 100000 measured market-data events and 50000 actual newly encoded orders after warm-up. `current.runNN.json/.csv` preserve all raw results. `current.csv/.svg` use run 1 only; the README table uses the twenty-run aggregate. `linux/micro.json` contains twenty Google Benchmark repetitions.

Scope: a two-sided single-instrument forced-quote workload on the full engine; no network or disk I/O in the timing loop. Tick-to-trade starts after parsing and ends after OUCH encoding. Book-stage timing includes validation/simulator bookkeeping; the separate add microbenchmark times the book operation. Stage totals do not sum exactly because order/no-order paths have different sample sets and percentile distributions cannot be added.

The measured Linux run is pinned on a shared GitHub x86-64 VM, with calibrated invariant TSC, GCC Release `-O3` and benchmark-only `-march=native`. The JSON captures the kernel, compiler, source digest and timer calibration. It does not certify IRQ isolation, CPU exclusivity, physical bare metal or a realistic full-day message distribution. Allocations count overridden C++ scalar/array/aligned allocation operators in the warmed core loop; dependency C allocation routines are not interposed.

`macos-*` and `micro-macos.json` are archived development diagnostics. Their steady_clock readings are coarse (some short stages quantize to zero); they do not establish latency targets. The initial root-level `docs/latency-macos.json` is the earlier no-order prototype harness and is retained as historical evidence only. Do not compare it to the current order-producing workload.
